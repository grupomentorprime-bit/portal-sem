# ADR-011 — Contrato mínimo Automatizaciones Growth OS V1

| Atributo | Valor |
| --- | --- |
| Estado | Aprobado · contrato |
| Fecha | 2026-09-06 |
| OT | [OT-GROWTH-AUTOMATION-001](../validation/OT-GROWTH-AUTOMATION-001/README.md) |
| Entrada | [ADR-005](./ADR-005.md), [ADR-006](./ADR-006.md), [ADR-008](./ADR-008.md), [ADR-010](./ADR-010.md), [OT-GROWTH-SALES-001](../validation/OT-GROWTH-SALES-001/README.md) |
| Alcance | Contrato V1 Automatizaciones (≠ Workflow); runtime mínimo vía AUTOMATION-003; sin WAIT ni editor |

---

## Decisión

Automatizaciones es una **capa reactiva por Espacio** sobre Growth Core y el Event Bus existente. No es el Workflow Engine, no es un segundo bus y no es un segundo Growth Core.

**Automatización ≠ Workflow de estados.**

| Pieza | Dueño | Pregunta que responde |
| --- | --- | --- |
| **Workflow** (`growth.opportunity`, ADR-005) | Estados de una Oportunidad | ¿En qué estado está la entidad? |
| **Automatización** (este ADR) | Reacción a hechos ya ocurridos | Si ocurre X y cumple Y, ¿qué operación reutilizable ejecutar? |

El Workflow sigue siendo el único motor de estados. La Automatización **puede** invocar una transición vía `sales-ops`; no redefine ni almacena la máquina de estados.

## REUTILIZA

| Capacidad | Origen | Uso en Automatizaciones |
| --- | --- | --- |
| Event Bus | ADR-006 / `core_events` | Fuente de Triggers (misma publicación que ya hace Growth Core) |
| Growth Core | ADR-010 | Contexto de Condición (origen, estado, `typeKey`, `nextAction`) |
| Workflow Engine | ADR-005 | Solo vía acciones que transicionan Oportunidad; **no** como almacén de Automatizaciones |
| `sales-ops` | SALES-001 | Únicas Acciones V1 contractuales |
| Identity / membresía | ADR-004 · ADR-008 | Permisos por Espacio; aislamiento `tenantId` |
| Actor sistema (patrón) | `growth-ingest` | Nuevo actor de sistema para ejecuciones automáticas (ver §Actor) |

**Prohibido reutilizar como almacenamiento de Automatizaciones:** `workflow_definitions`, `workflow_instances`, `workflow_history`. Esas colecciones siguen siendo del motor de estados.

## CONTRATO

### Modelo conceptual

```text
Evento → Trigger → Condición → Acción → Espera → Reanudación → Resultado
```

| Etapa | Significado |
| --- | --- |
| **Evento** | Domain Event ya persistido en `core_events` |
| **Trigger** | Selector de tipo(s) de evento que despiertan la Automatización |
| **Condición** | Predicado sobre el contexto Growth del Espacio (antes de actuar) |
| **Acción** | Operación reutilizable (`sales-ops`) sobre una Oportunidad del mismo `tenantId` |
| **Espera (WAIT)** | Pausa temporal antes de continuar (contrato conceptual; **no habilitada** en V1) |
| **Reanudación** | Continuación tras WAIT (misma definición; requiere runner de programados) |
| **Resultado** | Éxito / no-match / error acotado al intento; no altera el Evento origen |

### Frontera explícita

| Es Automatización | No es Automatización |
| --- | --- |
| Reaccionar a un `Growth*` publicado | Definir estados `open` → `active` → … |
| Filtrar por origen / estado / tipo / próxima acción | Attribution, campañas, inbox |
| Ejecutar `salesTransition*` / follow-up / nextAction | Enviar email Growth, WhatsApp, IA |
| Correr con actor de sistema del Espacio | Impersonar al visitante que originó el evento |

### Pertenencia y versión

- Toda Automatización **pertenece obligatoriamente** a un Espacio (`tenantId`). Sin definición global compartida entre clientes.
- Es **versionada**: cambios de Trigger/Condición/Acción producen versión nueva; ejecuciones futuras apuntan a una versión concreta. (Forma de persistencia: OT de implementación; este ADR no crea colecciones.)

### Triggers iniciales (V1 contractual)

Únicamente eventos **Growth*** reales ya registrados:

| Tipo |
| --- |
| `GrowthPersonaUpserted` |
| `GrowthOpportunityOpened` |
| `GrowthOpportunityTransitioned` |
| `GrowthActivityRecorded` |
| `GrowthNextActionSet` |
| `GrowthHandoffRecorded` |

Fuera de V1 contractual: eventos CMS/Identity/Workflow genéricos, webhooks externos, “respondió / no respondió”, timers como trigger primario.

### Condiciones iniciales (V1 contractual)

Evaluadas sobre la Oportunidad (y su Persona/Origen) del mismo `tenantId` que el evento:

| Condición | Campo / regla |
| --- | --- |
| Origen | `origin.kind` (y, si se declara, `channel` / `formDestination` ya presentes en el snapshot) |
| Estado | `status` (espejo Workflow) |
| Tipo de oportunidad | `typeKey` |
| Próxima acción | presencia (`nextAction != null`) o ausencia (`nextAction == null`) |

Sin expresiones libres, sin SQL, sin nodos visuales, sin condiciones sobre “mensaje respondido”.

### Acciones iniciales (V1 contractual)

Exclusivamente operaciones reales de `src/lib/growth/sales-ops.ts` (o su evolución in-place):

| Acción | Función |
| --- | --- |
| Transicionar Oportunidad | `salesTransitionOpportunity` |
| Registrar nota / contacto | `salesRecordFollowUp` |
| Fijar próxima acción | `salesSetNextAction` |
| Limpiar próxima acción | `salesClearNextAction` |

Toda Acción corre con el **actor de sistema** de Automatizaciones (abajo), no con el `userId` del visitante del Domain Event.

### Actor de sistema

| Actor | Quién | Uso |
| --- | --- | --- |
| Operador humano | `identity_users` del Espacio | Ventas / UI (`actorUserId` de sesión) |
| Ingestión | `growth-ingest` | Cableado de fuentes → Growth Core |
| **Automatización** | `growth-automation` (identificador de sistema) | Ejecuciones automáticas |

Reglas:

- El visitante / `userId` del Evento **no** se reutiliza como `performedBy` / `actorUserId` de la Acción.
- El Evento conserva su causa (`causationId` / payload); la Actividad resultante registra el actor de sistema.
- El actor de sistema **no** es una cuenta Identity ni un permiso humano.

### Permisos propuestos

| Legacy / registry | Granular (catálogo) | Intención |
| --- | --- | --- |
| `growth.automations.view` | `growth.automations.view` | Ver definiciones del Espacio |
| `growth.automations.manage` | `growth.automations.manage` | Crear / versionar / activar / desactivar |

Membresía del Espacio (ADR-004). No implica `growth.sales.operate` automáticamente en V1 contractual (la ejecución futura usa actor de sistema; la gestión de definiciones es otro permiso). Asignación a roles de plantilla: OT de implementación.

### Aislamiento multi-tenant

| Regla | Detalle |
| --- | --- |
| Campo canónico | `tenantId` en toda definición e intento |
| Trigger | Solo eventos cuyo `tenantId` = Espacio de la Automatización |
| Condición / Acción | Solo entidades Growth del mismo `tenantId` |
| Query | Filtro `tenantId` primero; sin match cruzado entre Espacios |
| Superficie futura | Admin del Espacio (`/admin`); **no** `/platform` |

### WAIT (habilitado con runner — AUTOMATION-005)

WAIT forma parte del modelo (`… → Acción → Espera → Reanudación → …`).

**Habilitado** cuando existe runner de `core_scheduled_events` ([OT-GROWTH-AUTOMATION-005](../validation/OT-GROWTH-AUTOMATION-005/README.md)): `schedule(GrowthAutomationResume)` + `flushScheduledEvents()` (claim atómico) fuera del request HTTP.

Contrato de pasos: `Trigger → Condición* → Acción+ → (Wait → Acción+)?`. Una sola espera; duración acotada. Sin UI de WAIT hasta OT explícita.

## LÍMITES

El contrato V1 **no** autoriza:

| Prohibido | Motivo |
| --- | --- |
| WAIT habilitado sin runner | Histórico; resuelto en AUTOMATION-005 |
| Colección persistente de runs/intentos | Runtime registra proyección fina `growth_automation_runs` ([OT-GROWTH-AUTOMATION-007](../validation/OT-GROWTH-AUTOMATION-007/README.md)); no es segundo Event Bus |
| Editor visual / nodos / canvas | Producto futuro |
| IA | Fuera de alcance |
| Email Growth / WhatsApp | No hay canal Growth; no inventar |
| “Respondió / no respondió” | No hay inbox ni señal de respuesta |
| Segundo Event Bus | Viola ADR-006 / ADR-010 |
| Segundo Workflow Engine | Viola ADR-005 / ADR-010 |
| Segundo Growth Core / `crm_*` | Viola ADR-010 |
| Reusar `workflow_definitions` como almacén de Automatizaciones | Confunde estado de entidad con reacción |

Runtime mínimo (subscriber + sales-ops): [AUTOMATION-003](../validation/OT-GROWTH-AUTOMATION-003/README.md).

## Alternativas descartadas

| Alternativa | Motivo |
| --- | --- |
| Guardar Automatizaciones en `workflow_definitions` | Mezcla estado de entidad con secuencias reactivas; rompe el corte ADR-005 |
| Triggers no-Growth* en V1 | Amplía superficie sin necesidad; los hechos comerciales ya están en Growth* |
| Acciones ad hoc (email, WhatsApp, HTTP) | No hay operaciones reales reutilizables; inventaría canales |
| WAIT “a medias” con solo `schedule()` | Persistir sin runner deja reanudaciones muertas |
| Ejecutar como el visitante del evento | Rompe auditoría y permisos; confunde captación con operación |
