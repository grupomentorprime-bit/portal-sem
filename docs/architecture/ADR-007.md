# ADR-007 — Portal Engine (CMS Driven Rendering)

| Atributo | Valor |
| --- | --- |
| Estado | Aprobado |
| Fecha | Junio 2026 |

## Contexto

El portal público evolucionó con secciones premium (`PortalHome`, `InstitutionSection`, etc.) donde el contenido venía del CMS pero el **orden y la estructura** seguían definidos en código React. Esto impedía personalización por tenant, landings de campaña y evolución sin despliegues.

OT-SEM-PORTAL-006 avanzó hacia bloques ordenados por CMS, pero la lógica permanecía dispersa en componentes sin un motor unificado.

## Decisión

Introducir el **Portal Engine** en `src/core/portal/` como capa oficial entre el CMS y los componentes React:

1. **Block Registry** — catálogo tipado de todos los bloques con version, resolver y componente UI.
2. **Visibility & Conditions** — evaluación de visibilidad por rol, feature flag, fechas y tenant.
3. **Resolvers** — datos vía Content Engine; componentes sin acceso directo a MongoDB.
4. **PortalRenderer** — único punto de renderizado de páginas públicas.
5. **SEO consolidado** — metadata y JSON-LD desde bloques + config.
6. **Eventos** — `PageViewed`, `BlockRendered`, `CTAViewed` para analytics futuro.

`PortalHome.tsx` queda como contenedor mínimo que invoca `PortalRenderer`.

## Consecuencias

### Positivas

* Home y páginas internas 100% CMS-driven.
* Multi-tenant y landings sin cambios de código.
* Preparado para audiencias (guest/student/teacher/admin) y feature flags por bloque.
* Integración con Event Bus y Asset Engine.

### Consideraciones

* `ServerBlockRenderer` (admin preview) coexiste para el Page Builder; el portal público usa `PortalRenderer`.
* Condiciones de rol requieren contexto de sesión en iteraciones futuras (hoy: `guest` en portal público).
* Bloques `html`/`markdown` permanecen `adminOnly`.

## Alternativas descartadas

| Alternativa | Motivo |
| --- | --- |
| Mantener switch en `PortalHome` | No escala; orden aún acoplado |
| Solo `ServerBlockRenderer` para todo | Componentes institucionales legacy, no premium |
| Headless CMS externo | Ya existe Page Builder + MongoDB |
