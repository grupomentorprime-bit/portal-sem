## Contexto

El uso de URLs manuales y archivos distribuidos dificultaba la reutilización, el control de referencias y la administración de recursos multimedia.

## Decisión

Los archivos binarios se almacenan en almacenamiento de objetos (o local en desarrollo), mientras que sus metadatos residen en MongoDB.

Toda imagen utilizada por la plataforma debe provenir de la Media Library.

El uso de recursos se controla mediante referencias (`usage`) para impedir eliminaciones inseguras.

## Consecuencias

### Positivas

* Gestión centralizada de activos.
* Eliminación segura.
* Optimización automática de imágenes.
* Compatibilidad con S3.
* Reutilización entre módulos.

### Consideraciones

* No se permiten URLs manuales en componentes.
* Todos los recursos deben pertenecer a un tenant.
* La biblioteca debe generar derivados optimizados cuando corresponda.

## Alternativas descartadas

* Carpeta pública sin metadatos.
* Subidas directas desde formularios.
* Almacenamiento embebido en documentos CMS.

## Implementación en el repositorio

Decisión materializada en v1.3.0 (`v1.3.0-media-library`):

| Decisión | Ubicación |
| --- | --- |
| Metadatos en MongoDB (`cms_media`) | `src/types/media.ts`, `src/lib/cms/media.ts` |
| Binarios en S3 o `public/media/` | `src/lib/cms/media-storage.ts` |
| Derivados WebP (400–1920px, thumbnail) | `src/lib/cms/media-processing.ts` |
| Referencias de uso | `src/lib/cms/media-usage.ts` |
| API REST | `src/app/api/cms/media/*` |
| UI admin y MediaPicker | `src/app/admin/media`, `src/components/media/*` |
| Alcance por tenant | `tenant` en documentos y prefijos de almacenamiento |

### Cumplimiento parcial (trabajo pendiente)

* Los consumidores (branding, bloques) persisten **URLs** en lugar de `mediaId`; conviene resolver en render.
* Sincronización de `usage` limitada a branding; falta en páginas y Content Engine.
* MediaPicker no desplegado en todas las entidades con imagen (programas, noticias, etc.).
* Guard de tenant ausente en rutas `[id]` y `bulk` de la API de media.

Detalle operativo, API y criterios de aceptación: [MEDIA-LIBRARY.md](../cms/MEDIA-LIBRARY.md).

Evolución v1.6.0: [OT-CORE-MEDIA-001](../ot/OT-CORE-MEDIA-001.md) — referencias por `mediaId` y Asset Engine.
